# Digital Signage Platform – Marketing Website / Landing Page

## Role

Jsi seniorní frontend developer, UX/UI designer a conversion-focused product designer.

Tvým úkolem je vytvořit **produkční, ultra-moderní a nadčasový marketingový web** pro naši digital signage platformu.

Nejde o interní administraci ani samotnou aplikaci pro televizory. Toto je **veřejný marketingový web**, jehož cílem je získávat dva typy zákazníků:

1. **Inzerenti** – firmy, které chtějí zaplatit za zobrazování své reklamy na našich obrazovkách.
2. **Provozovatelé / majitelé lokalit** – firmy nebo lidé, kteří mají vhodné místo pro umístění naší reklamní televize a chtějí za její umístění získávat provizi.

Web musí působit jako skutečný moderní technologický startup / SaaS produkt, ne jako běžná firemní stránka.

# Section: Jak to funguje

Vysvětli systém ve 3 jednoduchých krocích.

## 01

### Vyberete si kampaň

Firma nám pošle reklamní spot a nastaví požadovanou kampaň.

## 02

### My ji dostaneme na správná místa

Reklama se zobrazí na naší síti obrazovek v relevantních lokalitách.

## 03

### Vaše značka je vidět

Reklama se opakovaně zobrazuje lidem přímo v místě, kde se pohybují.

Použij moderní vizualizaci procesu.

---

# Section: Proč digital signage

Vysvětli výhody oproti klasické reklamě.

Například:

### Viditelnost

Reklama je přímo v prostoru, kde se lidé pohybují.

### Lokální zásah

Možnost cílit reklamu podle konkrétních lokalit.

### Opakovaný kontakt

Spot se během dne opakovaně zobrazuje.

### Jednoduchá správa

Kampaň řešíme digitálně bez nutnosti fyzické instalace ze strany klienta.

### Flexibilita

Obsah lze měnit a aktualizovat.

# Resend integration

Formuláře musí být skutečně funkční.

Použij:

**Resend**

API key nikdy nevystavuj ve frontendu.

Použij server-side endpoint / server action / API route podle architektury projektu.

Environment variable:

```env
RESEND_API_KEY=
```

Po odeslání formuláře:

1. validuj data
2. odešli e-mail přes Resend
3. odešli lead na náš interní e-mail
4. uživateli zobraz success stav
5. ošetři loading/error stavy

Nikdy neukládej API key do client-side kódu.

Použij validaci například přes Zod.
